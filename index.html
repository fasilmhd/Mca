Every page you load is
a conversation.

A client asks, a server answers, and the reply is assembled from layers of code you never see. This page traces that exchange — from the two machines talking, to the request that starts it, to the servers that keep the answer dynamic.

C/S

Client / Server

Client

A client is any program or device that initiates a request for a resource or service over a network, rather than providing one itself. A web browser is the most common example: it asks a server for a page and then displays whatever comes back.

Clients are typically lightweight and user-facing. They don't need to know how the resource was produced, only how to ask for it and how to render the reply.

Server

A server is a program or device that listens continuously for incoming requests and responds by supplying the requested resource or performing the requested action. One server can hold open connections with many clients at once.

The relationship is defined by roles, not hardware — the same machine could act as a client to one service while serving as a server to another.

TIER

Components of a Web Application

A web application is rarely one block of code. It's usually split into layers, each responsible for a single concern, so that changing how data is stored doesn't mean rewriting how it's displayed.

01

View Layer

The presentation layer — what the user actually sees and interacts with. It renders HTML, CSS and on-screen elements, and passes user actions (clicks, form input) inward to the layer below.

02

Business Layer

The logic layer — it applies the application's rules, makes decisions, validates input, and coordinates the exchange of information between the view and the data below it. This is where "what should happen" gets decided.

03

Data Access Layer

The storage layer — it handles reading from and writing to a database or file store, and hands clean, structured data back up to the business layer on request.

MIME

Types of Web Content

A single page can deliver several kinds of media at once, each requiring different handling by the browser.

Text

The written content of a page — headings, paragraphs, labels — marked up with HTML so the browser knows how to structure and style it.

Images

Static visual content such as photographs, illustrations and icons, typically in formats like JPEG, PNG or SVG.

Audio

Sound content — music, narration, effects — embedded and played back directly in the browser without a separate app.

Animation

Content that changes over time: CSS transitions, animated GIFs, or scripted motion used to guide attention or show state change.

HTTP

HTTP and the HTTP Request

Definition

HTTP (HyperText Transfer Protocol) is the application-layer protocol that governs how a client and server exchange messages on the web. It defines a shared format for asking for a resource and for replying with one, so that any browser can talk to any server.

Request and response

Request
  • Request linemethod, URL, HTTP version
  • Headersmetadata — host, accepted content, cookies
  • Bodyoptional — data sent with the request
Response
  • Status lineHTTP version, status code, reason
  • Headersmetadata — content type, length, caching
  • Bodythe actual resource — HTML, JSON, an image

How the communication works

The client opens a connection to the server and sends a request built from the fields above. The server parses it, carries out whatever work is needed, and sends back a response with a status code summarising the outcome — 200 for success, 404 when the resource isn't found, 500 for a server-side error. By default each exchange is stateless: the server treats every request independently unless something like a cookie is used to link them together.

DOM

Dynamic Web Pages

A dynamic web page is one whose content is generated or changed at the time it's requested, rather than being a fixed file that looks the same to everyone. The server (or the browser, via scripts) assembles the page using current data — the time, the logged-in user, the contents of a database — so the same URL can produce a different result on every visit.

Characteristics

  • Content varies by user, time, or input
  • Reads from and writes to a database
  • Can update in place without a full reload
  • Supports interaction — forms, logins, search

Examples

  • A social media feed personalised per user
  • An e-commerce page showing live stock and price
  • A webmail inbox
  • A dashboard that updates as new data arrives
APP

Application Servers

An application server is the environment that runs a web application's business logic — the middle layer between a web server, which handles raw HTTP traffic, and a database, which holds the data. Where a web server mainly serves static files and forwards requests, the application server executes the actual code: processing form submissions, applying rules, and generating the dynamic content that gets sent back.

Beyond running the application's logic, it typically provides shared services the application would otherwise have to build itself — session and transaction management, connection pooling to the database, load balancing across multiple instances, and security controls such as authentication. Familiar examples include Apache Tomcat, JBoss/WildFly, and Microsoft's IIS application services.
